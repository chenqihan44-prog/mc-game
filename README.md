# 方野：余烬灯塔

Windows 单人离线体素生存与建造游戏的开发版本。原计划见 [docs/开发计划.md](docs/开发计划.md)，真实进度与未通过关卡见 [docs/实施进度.md](docs/实施进度.md)。目前是可以运行的样板，不是已完成 S0–S7 验收的产品。

## 运行

本次成品体验版为 `builds/EmberLighthouse-presentation试玩包.zip`；完整解压后双击 `EmberLighthouse.exe`。也可运行 `builds/EmberLighthouse-presentation/EmberLighthouse.exe`。保留同目录 `.pck` 和 `data_EmberLighthouse_windows_x86_64`，不能只复制 EXE。发布包包含 .NET 运行时，无需安装编辑器或 SDK。

新版加入图形3×3工作台、94种物品图标、挖掘裂纹/碎屑/进度条、3D角色预览与第一人称持物动画。按最新试玩反馈，开发阶段优先补齐成品体验，完整Bug回归与S7测试留到内容完成后。具体操作见 [成品体验更新](docs/成品体验更新.md)。

在主菜单创建世界，输入整数种子；默认生存，另有休闲难度与创造模式。推荐种子 42 用于回归场景，尚未经过真人试玩推荐。

| --- | --- |
| 移动 / 跳跃 | WASD / Space |
| 蹲伏防坠 / 疾跑 | Shift / Ctrl |
| 挖掘、攻击 / 放置、进食、播种 | 鼠标左键 / 右键 |

| 旋转建筑 / 地图 | R / M |

界面使用原版 MC Java 版常见布局：底部 9 格图标快捷栏、生命心形、饥饿图标、经验条和水下气泡；F3 切换调试信息。背包分为 27 格储物区和独立快捷栏，并有可使用的 2×2 合成区。左键取放整组，右键取半或放一个，Shift 快捷移动，支持拖拽；关闭界面时合成格与鼠标上的物品会归还，溢出留在脚下可回收背包中。设置中可重绑定按键。

## 生存路线

1. 出生地有原木、碎石、莓果。左键获取，C 制作木板、木棍、石镐。
2. 制作工作台、营火和木箱，右键放置，Q 使用；营火附近有 7 格安全区。
3. 进入附近洞穴，采煤与粗铁；工作台制作熔炉，Q 冶炼。返回游戏后计时，Q 的容器界面取出产物。
4. 在出生点东南约 `(32,24)` 的废营地木箱找到作物与材料。制作种子，放置耕地，右键播种，成熟后 Q 收获。
5. 制作床设复活点，夜间使用可过夜。标准死亡保留多份可取回背包，M 查看位置。
6. 用铁镐获得晶矿、制作高阶工具与灯塔符印。地图显示三座灯塔，修复消耗符印与铁；灯塔旅行消耗煤且附近不能有敌人。

世界水平 4096 格、高 192 格，静态水支持游泳。没有动态流体与水桶搬运。暂停和失焦会停止世界模拟。

## 存档

正常运行放在 `%APPDATA%/Godot/app_userdata/方野：余烬灯塔/worlds`。世界数据、背包、设施、死亡背包、作物与进度以统一代际提交，保留最近三代有效存档；遇到损坏会尝试恢复完整代际并提示，无法恢复时保留原文件并报错。

每 60 秒自动保存，暂停菜单可手动保存与备份。主菜单可读取和备份已有世界。备份放在同级 `backups`；目前尚无游戏内备份恢复入口，请保留原目录再使用备份文件恢复。保存失败会显示错误并阻止正常的保存退出流程。

## 构建与验证

```powershell
.\tools\bootstrap.ps1 -Templates
.\tools\build.ps1 -Test -Export
```

锁定 Godot 4.6 stable .NET、.NET SDK 8.0.425 与配套导出模板。工具下载及 SDK 校验在 bootstrap 中；Godot 包使用官方发布 SHA-256，SDK 使用官方 SHA-512。Godot SDK 从编辑器附带的本地 NuGet 源读取。中文工程路径下使用临时目录中的 ASCII SDK 路径，避免引擎探测乱码。测试时应用目录重定向在工作区，正常发布包使用系统应用数据目录。

核心测试为独立 .NET 可执行程序，无测试框架下载依赖；涵盖坐标、确定性、网格、背包事务、计时产出、连续死亡、校验恢复、未来版本拒绝及五个真实进程中断点。运行报告位于 `test-results`。场景检查不能替代长期人工游玩或真人试玩。

素材来源见 `assets/LICENSES.md`；发布包包含 Godot 与第三方版权声明。

## 项目文件整理

`builds` 仅保留当前 `EmberLighthouse-presentation` 目录、对应试玩 ZIP 和 SHA256 清单。旧导出目录及压缩包已清理，历史测试记录与测试存档归档到 `test-results/archived-builds`；历史报告中的旧包路径仅记录当时的验证对象，不能用于重新验证已删除的包。

格式 2/3 的真实旧版 DLL 与 GodotSharp 依赖保存在 `tests/fixtures/published-format2`、`tests/fixtures/published-format3`，供 `tools/test-save-compat.ps1 -OldFormat 2` 或 `-OldFormat 3` 使用；迁移脚本默认使用 `tests/fixtures/published-format3/worlds` 中保留的格式 3 世界和当前版本 DLL。试玩包、源码、开发工具链、测试证据各有用途，请勿将它们当作重复文件删除。

本项目仅配置 Windows x64 导出，保留对应模板；已解压的工具下载包和其他平台模板已清理。`bootstrap.ps1 -Templates` 在所需 Windows 模板完整时复用现有文件。清理明细见 `test-results/project-cleanup.json`。

## Git 仓库

版本控制包含源码、资源、配置、文档、构建脚本和必要的历史兼容性测试输入。`.gitignore` 排除工具下载、Godot 缓存、编译输出、试玩包、生成的测试报告和本地敏感配置；试玩包可单独作为 GitHub Release 附件发布。

新克隆的仓库没有 `builds`、`.tools` 和 `test-results`，请先执行上面的引导和构建命令。历史试玩包校验报告仅保留在本地，不随源码提交；旧存档回归的固定输入见 `tests/fixtures/README.md`。
